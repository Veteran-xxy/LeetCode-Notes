# 283. 移动零 Move Zeroes

- 难度：Easy
- 主要知识点：数组、双指针、原地修改
- 使用语言：C++
- 日期：2026-09-27
- 状态：已在 LeetCode 通过

## 一、题目理解

把数组里的零移到末尾，非零元素的先后顺序保持不变。需要直接修改传入的数组，不能另建一个数组作为结果。

## 二、我的第一思路：逐个交换零

我最先想到的是遍历数组，遇到零就和后一个元素交换，让它一步步移动到末尾，再去处理下一个零。这个办法能保持非零元素的顺序，但同一个非零元素可能被反复交换。例如 `[0,0,0,1]` 里的 `1` 会向左移动三次。我当时回答了“6 次”，后来分清了整个过程的交换次数和单个数字的移动次数。

若逐个移动零，最坏情况下会做很多次相邻交换，时间复杂度为 `O(n²)`，额外空间为 `O(1)`。

## 三、改进思路：给非零元素安排位置

在 Codex 的提示下，我改为想“非零元素应该放在哪儿”：对于 `[0,1,0,3,12]`，`1` 放到下标 `0`，`3` 放到下标 `1`，`12` 放到下标 `2`。我最初说“插入到首位”，进一步想清楚后发现，位置应该随着找到的非零元素不断往后走，否则后面的数字会覆盖前面的数字。

代码里的 `i` 负责从左到右读取，`loc` 表示下一个非零元素该放的位置。只有遇到非零元素，`loc` 才前进，因此非零元素会按原顺序排在数组前面。

## 四、我通过的代码

最终代码也保存在 [solution.cpp](./solution.cpp)：

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int loc = 0;
        for(int i = 0; i < nums.size(); i++){
            if(nums[i] != 0){
                int mid = nums[i];
                nums[i] = 0;
                nums[loc] = mid;
                loc++;
            }
        }
    }
};
```

讨论思路时，我原本打算把剩余位置统一填零；实际代码没有第二次填零循环。原因是每次搬动非零元素时，先用 `mid` 保存它，再把原位置清零，然后写入 `nums[loc]`。这样处理完后，后面自然留下零。即使 `loc == i`，这段代码也会先清零再用 `mid` 写回，结果仍然正确。

## 五、复杂度和后续优化

时间复杂度为 `O(n)`：`i` 只遍历数组一次。额外空间复杂度为 `O(1)`：只用了几个变量，没有复制数组。每个元素都需要检查，所以时间复杂度在数量级上已经无法继续降低。

通过后我问能否继续优化。Codex 指出，可以减少赋值次数：当 `loc == i` 时，元素本来就在正确位置，无须先清零再写回，但仍要让 `loc` 前进。另一种写法是先依次写入非零元素，最后把剩余位置填零；它在某些输入下写入更少，但全零数组会比我现在的代码多写入，所以不能说对所有输入都更优。这些是通过后的改进方向，仓库中的 `solution.cpp` 仍保留我实际通过的代码。

## 六、本题学到的 C++ 和算法知识

- `vector<int>& nums` 是引用参数，修改 `nums` 就是在修改原数组；函数返回 `void`，不用返回新数组。
- `nums.size()` 是元素个数，遍历条件用 `i < nums.size()`，避免越界。
- `mid` 暂存当前非零值，避免清零时把要移动的值丢掉。
- 双指针可以让一个下标负责读取，另一个下标负责确定写入位置；本题还要求非零元素的顺序不变。
