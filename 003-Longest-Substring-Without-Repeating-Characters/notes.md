# 3. 无重复字符的最长子串 Longest Substring Without Repeating Characters

## 一、题目理解

给定字符串 `s`，找出其中没有重复字符的最长连续片段，返回它的长度。返回的是整数，不是子串本身。

这里最容易忽略的是“连续”：`"pwwkew"` 中的 `"wke"` 是子串，但跳过中间字符得到的 `"pwke"` 只是子序列。空字符串的答案是 0；数字、符号和空格也要当作字符处理。

## 二、动手前补的 C++ 基础

我先让 Codex 参考之前的“C++基础梳理”对话，只讲基础语法，不提前给解题思路。随后又问了字符数组怎么定义、不写长度怎么写，以及如何判断字符是否存在于字符串中。

```cpp
char c = 'a';
string s = "abc";
char arr[] = {'a', 'b', 'c'};  // 3 个字符
char text[] = "abc";          // 4 个字符，末尾包含 '\0'
```

`char` 表示单个字符，字符字面量使用单引号；双引号的字符串字面量可以用来初始化 `string`。`s[i]` 的类型是 `char`，所以比较字符时写 `s[i] == 'a'`。`'1'` 是字符，`1` 是整数；`' '` 是一个空格字符。

省略字符数组长度时，需要提供初始化内容供编译器推断，不能只写 `char arr[];`。固定数组不能自动增长；`string` 可以用 `push_back(c)` 追加字符。题目已经提供 `string s`，可以直接访问 `s[i]`，不需要转成字符数组。

`s.size()` 和 `s.length()` 都返回长度，下标从 0 开始，遍历字符时条件应为 `i < s.size()`。`string s` 是值传递；之前第一题的 `vector<int>& nums` 是引用传递。

我在第一版代码中用到的查重语法是：

```cpp
if (s.find(c) != string::npos) {
    // 找到了字符 c
}
```

`string::find()` 返回第一次出现的位置，找不到时返回 `string::npos`。不能直接用 `if (s.find(c))` 判断存在，因为找到的下标可能是 0。

## 三、我的第一版：用字符串记录见过的字符

我定义了 `string findc` 保存字符，用 `cnt` 计数。遍历输入字符串时，如果字符不在 `findc` 中，就追加进去并增加计数。最初我还在外层循环里加了一层循环：

```cpp
string findc;
int cnt = 0;
for (int i = 0; i < s.size(); i++) {
    char c = s[i];
    for (int j = 0; j < findc.size(); j++) {
        if (findc.find(c) == string::npos) {
            findc.push_back(c);
            cnt++;
        }
    }
}
```

Codex 检查后指出：`findc` 初始为空，内层循环第一次判断就是 `0 < 0`，循环体根本不会执行，字符串永远没有机会加入字符。按代码推演，这版总会返回 0；这一点不是截图中的实际运行结果。

此外，`find()` 本身已经会查找字符串，内层循环没有必要，变量 `j` 也没有参与查找。我随后去掉了内层循环。

## 四、去掉内层循环后：不同字符数量不等于最长子串长度

我保留了“没见过就加入，见过就跳过”的处理。运行三个示例时，前两个通过，但 `"pwwkew"` 输出 4，预期是 3。

这版最终保存的是 `"pwke"`：第二个 `w` 被跳过了，后面的 `k`、`e` 仍然接上去。虽然保存的字符没有重复，它们却不是原字符串中的连续片段。

这里我才分清：统计整个字符串中不同字符的数量，并不能回答最长连续子串的问题。重复发生时，需要调整当前片段，而不是简单跳过当前字符。

## 五、我尝试清零、清空，再保存最大值

### 1. 只清零计数，没有调整字符串

遇到重复字符时，我先写了：

```cpp
if (findc.find(c) != string::npos) {
    cnt = 0;
}
```

这样 `findc` 仍保留原来的字符，`cnt` 却变成 0，两者不再对应。例如 `findc == "pw"` 时遇到第二个 `w`，字符串还是 `"pw"`，计数却是 0。Codex 手动推演指出，这版对 `"pwwkew"` 最后会返回 0。

### 2. 同时清空字符串，仍然丢失之前的最大长度

我又在重复时加上 `findc = "";`。这次运行 `"abcabcbb"`，实际输出 1，预期是 3。

遍历前三个字符时，我已经得到过 `"abc"`，长度是 3；后面清空并重新计数，最后只留下 `"b"`，于是返回 1。`cnt` 只是当前片段的长度，不能兼任整个过程的最大长度。

根据 Codex 的提示，我增加了 `cntmax`，每当 `cnt` 更大就更新它，最后返回 `cntmax`。

### 3. 三个示例通过，但完整提交在 `"eea"` 上失败

加上 `cntmax` 后，三个示例都通过了。我提交到力扣，截图显示通过了 613 / 1036 个测试用例，失败输入是 `"eea"`：输出 1，预期是 2。

原因是 `push_back(c)` 仍然放在 `else` 中。遇到第二个 `e` 时，我清空了之前的内容，但没有加入当前这个 `e`；之后只保存了 `"a"`，漏掉了合法子串 `"ea"`。

Codex 还指出，全部清空也会丢失可保留的后缀。例如 `"dvdf"` 中遇到第二个 `d`，应该保留 `"v"` 并接上当前 `d`，后面再接 `f`，形成 `"vdf"`。只清空再加入当前字符，仍会漏掉这类答案。

## 六、Codex 帮我修改的字符串版本

我明确让 Codex 帮我改好后，它提供了保留无重复后缀的写法，核心操作如下：

```cpp
auto pos = findc.find(c);
if (pos != string::npos) {
    findc.erase(0, pos + 1);
}
findc.push_back(c);
int cnt = static_cast<int>(findc.size());
```

遇到重复时，删除从开头到旧的重复字符为止的前缀，再加入当前字符。例如 `findc == "abc"`，当前字符是 `b`，删除 `"ab"` 后保留 `"c"`，再加入 `b` 得到 `"cb"`。

这个版本由 Codex 提供，不是我最初独立写出的解法。对话中没有确认它的完整提交结果；最终选择保存的是下一节的哈希集合滑动窗口版本。

## 七、参考题解后学习滑动窗口

我发来一张题解截图，请 Codex 详细解释上面的 C++ 代码。截图中的作者显示为 powcai，题解标题为“滑动窗口”。最终保存的代码来自这份参考题解，我已确认这版在力扣完整提交通过。

窗口就是原字符串中一段连续范围。`left` 表示左端下标，`i` 表示右端下标，`lookup` 记录当前窗口有哪些字符，`maxStr` 保存历史最大长度。无需另外复制整个子串。

每轮开始时，集合保存上一轮的窗口 `s[left ... i - 1]`，当前的 `s[i]` 尚未加入：

1. 如果 `s[i]` 已在集合中，就从左端逐个移除字符，并增加 `left`。
2. 直到旧的重复字符离开窗口，才可以加入当前字符。
3. 当前窗口的长度是 `i - left + 1`，用它更新最大值。

截图代码先更新最大长度，再插入当前字符。这个顺序可以成立，因为重复已经处理完，左右下标已经确定新窗口的范围，长度计算不依赖集合是否已经插入当前字符。

### 为什么是 `while`，不能只用 `if`

对于 `"pwwkew"`，准备加入第二个 `w` 时，原窗口是 `"pw"`。第一次移除的是左端的 `p`，但旧的 `w` 还在；还需要移除旧的 `w`，才能加入新的 `w`。只执行一次的 `if` 不足以解决重复。

```cpp
while (lookup.find(s[i]) != lookup.end()) {
    lookup.erase(s[left]);
    left++;
}
```

`erase(s[left])` 删除的是集合中的字符值，`left++` 则同步调整窗口边界。原字符串没有被修改。不能只从集合删除旧的重复字符、却保留它前面的字符，否则会跳过中间位置，破坏连续性。

### 手动推演 `"pwwkew"`

以下是每轮处理完成后的状态：

| `i` | 当前字符 | 从左端移除 | `left` | 当前窗口 | 长度 | `maxStr` |
|---|---|---|---|---|---|---|
| 0 | `p` | 无 | 0 | `"p"` | 1 | 1 |
| 1 | `w` | 无 | 0 | `"pw"` | 2 | 2 |
| 2 | `w` | `p`、旧的 `w` | 2 | `"w"` | 1 | 2 |
| 3 | `k` | 无 | 2 | `"wk"` | 2 | 2 |
| 4 | `e` | 无 | 2 | `"wke"` | 3 | 3 |
| 5 | `w` | 下标 2 的旧 `w` | 3 | `"kew"` | 3 | 3 |

每次只移除解决重复所必需的前缀，所以处理完右端点 `i` 后，得到的是以该位置结尾的最长无重复子串。比较所有右端点对应的长度，就能得到全局最大值。

## 八、最终通过的代码

代码也保存在 [solution.cpp](./solution.cpp)，保持确认通过的逻辑，没有添加 `main()`：

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        if (s.size() == 0) return 0;

        unordered_set<char> lookup;
        int maxStr = 0;
        int left = 0;

        for (int i = 0; i < s.size(); i++) {
            while (lookup.find(s[i]) != lookup.end()) {
                lookup.erase(s[left]);
                left++;
            }

            maxStr = max(maxStr, i - left + 1);
            lookup.insert(s[i]);
        }

        return maxStr;
    }
};
```

## 九、复杂度

设字符串长度为 `n`，字符种类数为 `Σ`。

- 时间复杂度平均为 `O(n)`。虽然有 `for` 和 `while`，但右端点 `i` 只向右走一遍，左端点 `left` 也只向右走一遍，每个字符被插入一次、最多移除一次。集合操作按平均 `O(1)` 分析，不能说哈希操作永远是 `O(1)`。
- 窗口维护的额外空间复杂度为 `O(min(n, Σ))`，集合最多保存这么多不同字符。粗略写为 `O(n)` 也成立；固定大小字符集下，集合空间有固定上限。这里按通常题解口径分析辅助空间，不计输入参数 `string s` 值传递时可能产生的字符串副本；若把副本计入，调用的额外空间可为 `O(n)`。

## 十、本题学到的 C++ 和最重要的收获

- `string::find()` 返回位置，找不到时为 `string::npos`；`unordered_set::find()` 返回迭代器，找不到时为 `end()`，两种判断方式不能混用。
- `unordered_set<char>` 只保存字符，`unordered_map<char, int>` 保存字符与整数的对应关系。集合不记录原字符串顺序，也不会因自动去重就替我保证窗口合法。
- `lookup.insert(c)` 插入字符，`lookup.erase(c)` 删除字符值。`lookup.erase(s[left])` 不是按下标删除集合元素。
- `findc.erase(0, pos + 1)` 的两个参数是起始位置和删除数量；`findc = ""` 或 `findc.clear()` 会全部清空。
- `auto` 可以推断 `find()` 返回值的类型；`static_cast<int>(findc.size())` 显式把字符串长度转换成整数。
- `max(a, b)` 返回较大值，`maxStr = max(maxStr, 当前长度)` 等价于我用 `if` 更新 `cntmax`。
- 函数返回 `int`，最终应返回最大长度。`return {};` 在 `int` 函数中合法，会返回 0，不能照搬第一题把它理解成空 `vector`；讨论开始时 Codex 说这里“不能写”并不准确。

这次我的学习过程是：记录见过的字符 → 发现连续性被破坏 → 尝试清零和清空 → 增加历史最大值 → 从 `"eea"` 的失败发现当前字符被漏掉 → 理解保留后缀 → 学习用下标和集合维护窗口。

我最需要记住的是：当前长度和历史最大长度要分开；遇到重复不能直接跳过当前字符，也不能随意清空所有内容。滑动窗口的关键是让“窗口范围”和“集合里的字符”始终对应，并且只移动到恢复合法为止。
